# Cosmic Laundry

The Cosmic Laundry storefront, running on Next.js.

## Run locally

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

## How it is put together

- `app/(storefront)/` serves the storefront at clean URLs: `/`, `/laundries`, `/laundries/<id>` and `/tees/<id>`
  (a tee opens over its Laundry). Every URL gets the same static HTML, with no React on it; `lib/storefront/page.ts`
  only sets each page's title, description, canonical link and share preview. Pages are cached and refreshed with the catalog.
  Old `#/` links still work: `public/app.js` rewrites them to the clean address.
- `/sitemap.xml` and `/robots.txt` list the shop pages. Set `SITE_URL` (e.g. `https://cosmiclaundry.lk`) so canonical and sitemap links use the real domain.
- `public/` holds the storefront's CSS, the vanilla JS that draws every shop page, fonts, product photos and GSAP.
- `/catalog.js` is generated by `app/(storefront)/catalog.js/route.ts` from the Supabase catalog. It's refreshed from Supabase at most every minute (admin saves show immediately). If Supabase isn't configured, it uses the snapshot in `lib/catalog/seed-data.ts`.

## Supabase

- `supabase/migrations/` holds the schema and the launch catalog: regions, Laundries, tees, colours, sizes and LK prices.
- Apply them to a project:

  ```bash
  npx supabase login
  npx supabase link --project-ref <your-project-ref>
  npx supabase db push
  ```

- Copy `.env.example` to `.env.local` and fill in the project URL and publishable key.
- `scripts/generate-catalog-seed.mjs` rebuilds the seed migration from `lib/catalog/seed-data.ts`. It's only needed for a fresh database. After launch, products are edited in the database (and later in the admin).

New pages like checkout and the admin will be regular Next.js React routes, kept apart from the storefront.

## Checkout (PAYable)

Guest checkout: basket → `/checkout` → PAYable hosted payment page → webhook → `/checkout/complete`.

- `app/(checkout)/` — the checkout and order-result pages (React, wearing the storefront's stylesheets).
- `app/api/checkout` — re-prices the basket on the server, saves a pending order, opens a PAYable session.
- `app/api/payable/webhook` — verifies PAYable's checkValue and amount, marks the order paid/failed (safe to receive twice).
- `app/api/orders/[number]` — order status for the customer's link; `/pay` starts a retry (`CL-1001-2`, ...).
- `lib/payable/` — Direct API client and checkValue signing. `supabase/migrations/*_orders.sql` — orders, lines, payment attempts, shipping rates.

Set `PAYABLE_MODE=mock` (the default outside production) to use a fake PAYable built into the app at `/mock-payable`,
with buttons to approve, decline, cancel, send the webhook twice or lose it. Switch to `sandbox` once PAYable sends
the sandbox keys, with `SITE_URL` set to a public https domain they have registered (they reject localhost).
See `.env.example` for every variable. Sri Lanka delivery is 500 LKR (`shipping_rates`).

## Admin (`/admin`)

Overview (sales today / this month, orders to ship, low stock), Orders (filter, search, pack/ship with courier and
tracking, mark paid/cancelled/refunded, CSV download) and Products (edit details, LK/UK/US prices, stock per colour
and size, show/hide, upload photos, add new tees).

- Sign-in is Supabase Auth (email + password). Only emails listed in `admin_users` get in; this is checked on the
  server for every admin page, action and download (`lib/admin/auth.ts`, and again in `db()` in `lib/admin/data.ts`).
- Reads and writes use `SUPABASE_SECRET_KEY` on the server. Product saves go through `admin_save_product` in one
  transaction and refresh `/catalog.js` straight away.
- Photos uploaded in the admin are prepared like the batch script (`lib/admin/images.ts`) and stored in the
  `product-images` Storage bucket; `products.image_base` points at them. Photos in `public/assets/products/` keep working.
- Stock is only tracked for sizes with a number; it goes down when an order becomes paid (database trigger).
- Schema: `supabase/migrations/*_admin.sql`.

**Add an admin:** Supabase → Authentication → Users → Add user (email + password, tick *Auto Confirm User*), then in the SQL editor:

```sql
insert into public.admin_users (email) values ('you@example.com');
```

## Regions and currencies (LK / UK / US)

- On the first visit `proxy.ts` picks the region from Vercel's `x-vercel-ip-country` (Sri Lanka → LK, UK → UK,
  everyone else → US) and saves it in the `cl_region` cookie. The LK / UK / US switcher (header, phone menu, footer)
  changes the cookie and reloads.
- Pages are the same for everyone; `/catalog.js` is rewritten to `/catalog/<region>` (cached per region), so prices,
  the basket and the WhatsApp message use 3,499 LKR, £19.99 or $24.99.
- Checkout charges in the region's currency through PAYable, delivers to that country and checks the phone in that
  country's format (`lib/region.ts`, `lib/checkout/shared.ts`).
- Prices per tee and region: admin → Products, or `product_prices`. UK/US delivery fees: `shipping_rates`
  (placeholder £0 / $0 until decided). Locally there's no geo header, so the default is LK; use the switcher.

## Custom Laundry (made to order)

The `custom` Laundry sells a plain tee ("Your Design", 4,999 LKR / £29.99 / $39.99). In the tee window the customer
uploads their design (PNG/JPG/WebP, shrunk in the browser), adds instructions, and buys it like any tee.

- Upload: `POST /api/custom-design` checks it's a real image and stores it in the private Storage bucket
  `custom-designs` (not the database). The basket keeps the design id, a small preview and the note.
- Checkout refuses a Custom tee without its design; the order line stores `design_path` and `design_note`.
- Admin → the order shows the design with a Download button and the instructions.
- Daily clean-up (`/api/cron/clean-designs`, Vercel Cron in `vercel.json`, needs `CRON_SECRET`): unused uploads after
  24 hours, unpaid orders' designs after 7 days, delivered/cancelled/refunded orders' designs after 30 days.
- Which Laundries need a design: `DESIGN_COLLECTIONS` in `public/commerce.js` and `collection === 'custom'` in
  `lib/checkout/pricing.ts`. It's kept off the home page strip and out of All tees.
